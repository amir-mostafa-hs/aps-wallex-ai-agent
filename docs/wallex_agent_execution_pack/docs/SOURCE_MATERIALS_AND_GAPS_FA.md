## 2. موارد منبع‌محور که حالا تأیید شده‌اند

- `assets.md`: معاملات Spot بدون leverage؛ فهرست ۳۴۵ جفت‌ارز غیرفعال در حساب اعتباری.
- PDF، صفحه ۱: طرح «۰ تومان دارایی ورودی + ۵,۰۰۰,۰۰۰ تومان اعتبار دریافتی برای ۳ روز»؛ امکان ساخت/مدیریت API در حساب اعتباری نمایش داده شده، در حالی که قابلیت بومی «بات معامله‌گر» و معامله تعهدی در جدول فعال نیستند.
- PDF، صفحه ۲: کارمزد معاملات حساب اعتباری از سطح ۱ آغاز می‌شود؛ درباره هشدار و liquidation صحبت می‌کند و در صورت liquidation می‌گوید دارایی یا مبلغی بازنمی‌گردد.
- `task.md`: زمان رقابت سه روز؛ ممنوعیت معامله دستی، self-trading، هماهنگی درون‌تیمی و wash trading؛ الزام source مطابق نسخه اجراشده، گزارش دلیل هر معامله، مستند Markdown و demo حدود ۵ دقیقه.
- `task.md` برای محاسبه بازدهی هم ارزش نهایی دارایی‌ها/unrealized P&L را ذکر می‌کند و هم تأکید می‌کند سود/ضرر باید در تومان realized شود و پایان نباید کوین باقی بماند؛ این عبارت‌ها در گزارش جدا نگه داشته می‌شوند و ساعت/روش رسمی پایان از برگزارکننده تأیید می‌شود.

## 3. تعارض‌ها یا ابهام‌های واقعی که نباید بی‌صدا رفع شوند

1. **شرط موجودی ثبت‌نام در PDF در کنار «۰ تومان دارایی ورودی»:** حد دقیق واجد شرایط بودن باید از حساب/برگزارکننده روشن شود.
2. **کارمزد اعتبار:** بنر PDF می‌گوید بازپرداخت اعتبار سه‌روزه رایگان است؛ بدنه PDF فرمول عمومی یک طرح ۳۰روزه و کارمزد روزانه را توضیح می‌دهد. هزینه همان طرح را قبل از Live مستقیماً تأیید کنید.
3. **جهت انتقال بین حساب‌ها:** متن PDF انتقال از اصلی به اعتباری را راه پیشگیری از liquidation ذکر می‌کند؛ جدول انتقال بین حساب‌ها را در ستون حساب اصلی فعال نشان می‌دهد، که با انتقال یک‌طرفه main→credit سازگار است. پیش از تکیه خودکار، عملیات واقعی تأیید شود؛ انتقال credit→main را فرض نکنید.
4. **بازدهی پایان رقابت:** متن هم ارزش نهایی و unrealized P&L را ذکر می‌کند و هم خروج به تومان/عدم نگهداری کوین را می‌خواهد. realized net P&L و equity نهایی جدا گزارش شوند؛ مبنای رسمی و deadline خروج تأیید شود.
5. **Scorecard:** جدول موجود در `task.md` به‌عنوان پیشنهاد امتیازدهی توصیف شده، درحالی‌که کاربر همان جدول را معیار کاری مسابقه اعلام کرده. بسته برای برنامه‌ریزی از جدول استفاده می‌کند؛ اگر برگزارکننده نسخه نهایی رسمی منتشر کرده، آن نسخه ملاک نهایی است.
6. **API جاری:** متن فایل هیچ endpoint مدرنی را به تنهایی تأیید نمی‌کند. endpointها، مجوزها، schema و rate limit باید با docs جاری و read-only API call تأیید شوند.
7. **زمان رسمی پایان اعتبار/مسابقه:** سه روز ذکر شده، اما ساعت دقیق شروع/پایان در فایل‌ها مشخص نیست.

## 4. حساب مبنا و جلوگیری از دو بار شمردن سرمایه

PDF عبارت «۰ تومان دارایی ورودی + ۵,۰۰۰,۰۰۰ تومان اعتبار برای ۳ روز» دارد؛ `task.md` نیز ۵ میلیون تومان را سرمایه مبنا می‌نامد. بنابراین ۵ میلیون تومان مبنای مسابقه است و نباید بدون مدرک به‌صورت ۵ میلیون سرمایه شخصی **به‌علاوه** ۵ میلیون اعتبار شمرده شود. عدد واقعی قابل‌استفاده باید از همان حساب اعتباری خوانده و با organizer brief تطبیق داده شود.

## 5. Gateهای غیرقابل مذاکره پیش از Live

- denylist مشتق‌شده را با API active Spot markets تطبیق بده؛ فقط باقی‌مانده‌ای که حساب واقعاً می‌تواند معامله کند در allowlist قرار گیرد.
- حساب و available balance، fee level، min-notional، quantity step، price tick و Toman/quote valuation را با API واقعی تأیید کن.
- آستانه هشدار و liquidation طرح اعتباری را مشخص کن؛ توان stop/exit واقعی و recovery/reconciliation را آزمایش کن.
- `MODE=shadow` پیش‌فرض است. Live فقط با preflight کامل و acknowledgment یک‌باره مجاز است؛ پس از فعال‌سازی مجاز، سفارش‌ها خودکارند.
- هرگز با «همه نمادها مجازند» fallback نکن؛ خطای universe، account mismatch، داده کهنه یا وضعیت سفارش نامعلوم باید fail closed کند.
