## 2. منبع‌های اصلی بازبینی‌شده

- `intro-text.md`: تمرکز روی موتور، استراتژی، معاملات خودکار، API/MCP، Backtest/Shadow و demo اجباری.
- `task.md`: سه روز اجرا، حساب تخصیصی ۵ میلیون تومانی، قوانین ممنوعیت، بازدهی، گزارش معامله، سورس قابل تطبیق با نسخه اجرا و جدول ارزیابی.
- `assets.md`: معاملات Spot بدون leverage؛ ۳۴۵ جفت‌ارز غیرفعال در حساب اعتباری.
- PDF دو صفحه‌ای: صفر دارایی ورودی + ۵ میلیون اعتبار سه‌روزه؛ API برای اعتبار نمایش داده شده؛ قابلیت بومی bot-trader و futures برای حساب اعتباری فعال نیست؛ هزینه تراکنش از سطح ۱؛ هشدار و ریسک liquidation.

جزئیات و تعارض‌های منابع در `docs/SOURCE_REVIEW_FA.md` و `docs/SOURCE_MATERIALS_AND_GAPS_FA.md` آمده‌اند.

## 3. نکات مهمی که در بازبینی منبع آشکار شد

- ۵ میلیون تومان، اعتبار تخصیص‌یافته/سرمایه مبنای چالش است؛ به معنی ۵ میلیون سرمایه خود تیم به‌علاوه اعتبار دوم نیست.
- PDF می‌گوید طرح در صورت liquidation دارایی یا مبلغی به کاربر بازنمی‌گرداند. ریسک liquidation باید از ریسک عادی پوزیشن جدا ارزیابی شود.
- بنر «بازپرداخت اعتبار ۳ روزه رایگان» در کنار مثال عمومی کارمزد طرح ۳۰روزه آمده؛ هزینه دقیق طرح جاری باید در account UI/با organizer تأیید شود.
- PDF انتقال از حساب اصلی به اعتباری را راه پیشگیری از liquidation ذکر می‌کند و جدول قابلیت انتقال را در ستون حساب اصلی نشان می‌دهد؛ این با مسیر یک‌طرفه main→credit سازگار است اما endpoint/عملیات باید پیش از اتکا تأیید شود.
- `task.md` هم unrealized P&L/equity نهایی و هم realized Toman/no coin at end را ذکر می‌کند. سیستم باید هر دو معیار را جدا گزارش کند و قبل از پایان، ساعت و روش رسمی close/valuation را تأیید کند.

## 4. مرز تصمیم‌گیری Agent و ایمنی

- LangChain تنها orchestration framework برای MVP است؛ یک Decision Agent با structured output مبتنی بر TypedDict/JSON Schema کافی است.
- هیچ Pydantic model مستقیم در کد دامنه تعریف نشود؛ TypedDict به‌تنهایی runtime validator نیست، پس Validator صریح Python لازم است. dependency ترانزیتی LangChain را کورکورانه حذف نکنید.
- Agent انتخاب واقعی Candidate/استراتژی/افق/پارامترهای مجاز انجام می‌دهد ولی ابزار ارسال/لغو خصوصی سفارش به Agent داده نمی‌شود.
- scanner، risk sizing، execution، reconciliation و P&L deterministic و تست‌پذیرند.
- Live فقط پس از market allowlist، account preflight، fee/precision/minimum checks، stop/recovery validation و order reconciliation فعال می‌شود.

## 5. نتیجه آزمون یکپارچگی

بعد از ساخت، این موارد باید دوباره اجرا شوند:

- بازکردن ZIP با `zipfile.testzip()`؛
- بررسی تمام فایل‌های Markdown از نظر UTF-8؛
- parse همه بلوک‌های JSON؛
- بررسی لینک‌های local Markdown؛
- کنترل اینکه تمام مسیرهای نسخه قبلی در نسخه جاری حاضر باشند؛
- کنترل دقیق برابر بودن نسخه‌های source_materials/originals با آپلودها؛
- مقایسه SHA-256های منبع و manifest.

در بازسازی این نسخه، هر چهار منبع با فایل‌های بارگذاری‌شده byte-for-byte یکسان بودند؛ ۳۴۵ بازار از `assets.md` استخراج شد و همه به همان ترتیب با فایل JSON تطبیق داده شدند. مسیرهای مستقیم نسخه قبلی به‌صورت ۲۱/۲۱ حفظ شدند و ZIP قبلی نیز به شکل snapshot آرشیوی در بسته قرار دارد. آزمون archive، صحت مالی/قانونی یا سودآوری را ثابت نمی‌کند. بسته اسناد و TODO است؛ خود ربات قبل از معامله واقعی باید تمام gateهای Preflight را اجرا کند.
